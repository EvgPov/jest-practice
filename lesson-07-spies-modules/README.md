# Лекция 7. Шпионы и мокирование модулей

Практика к теме подмены **импортированных** зависимостей: `jest.mock` (подменить целый модуль) и `jest.spyOn` (приставить наблюдателя к реальной функции).

> **Отличие от Лекции 6.** В прошлой лекции зависимость мы **передавали аргументом** и подменяли через `jest.fn()`. Здесь функция сама **импортирует** нужный модуль — передать двойника при вызове уже нельзя, поэтому подменяем сам модуль (`jest.mock`) или следим за функцией на месте (`jest.spyOn`).

Два задания, файлы в `src/`:

- `currency.js` (готов, **не менять**) + `convert.js` / `convert.test.js`
- `logEvent.js` / `logEvent.test.js`

## Задание 1. `convertToRub` — мокируем импортированный модуль

Файл `currency.js` — это «внешний» модуль курсов валют: его функция `getRate(code)` в реальности ходила бы на сервер. **Менять его не нужно** — в тесте вы подмените его целиком.

Реализуйте `convertToRub(amount, code)` в `convert.js`:

**Спецификация.**

- функция импортирует `getRate` из `./currency.js`;
- возвращает `amount * getRate(code)` — сумму, переведённую в рубли по курсу.

**Тесты.** Настоящий курс из сети нам не нужен — подмените весь модуль:

- [ ] `jest.mock("./currency.js")` — подменить модуль авто-моками.
- [ ] Задать ответ: `getRate.mockReturnValue(90)`.
- [ ] Проверить результат: `convertToRub(2, "USD")` → `180`.
- [ ] Проверить, что `getRate` вызван с нужным кодом: `toHaveBeenCalledWith("USD")`.

> `jest.mock(...)` автоматически «поднимается» в начало файла — поэтому модуль подменён ещё до импорта. Так и должно быть.
>
> **Важно (Jest 30):** путь в `jest.mock` регистрозависим — пишите его точно как в `import` (`"./currency.js"`, не `"./Currency.js"`).

## Задание 2. `logEvent` — шпионим за `console.log`

Реализуйте `logEvent(name)` в `logEvent.js`:

**Спецификация.**

- вызвать `console.log` со строкой вида `"Событие: click"` (то есть `"Событие: " + name`);
- вернуть `true`.

**Тесты.** `console.log` — реальная функция, которую мы не передавали аргументом. Приставим к ней **шпиона**:

- [ ] `const spy = jest.spyOn(console, "log").mockImplementation(() => {})` — следим за `console.log` и заодно глушим вывод в консоль.
- [ ] Вызвать `logEvent("click")` и проверить `spy` через `toHaveBeenCalledWith("Событие: click")`.
- [ ] В конце вернуть оригинал: `spy.mockRestore()`.

> Без `.mockImplementation(() => {})` шпион всё равно вызовет **настоящий** `console.log` (шпион по умолчанию только наблюдает) — тест пройдёт, но засорит вывод. `mockRestore()` в конце возвращает нормальное поведение `console.log` для других тестов.
