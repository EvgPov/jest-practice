# Лекция 8. Жизненный цикл теста

Практика к теме хуков `beforeEach` / `afterEach` и борьбы с **протеканием состояния** — когда след одного теста ломает другой. Главная цель — научиться готовить каждому тесту чистую сцену.

Два задания, файлы в `src/`:

- `counter.js` / `counter.test.js`
- `saveAll.js` / `saveAll.test.js`

> **Суть темы.** Тесты должны быть независимы: их запускают в любом порядке и пачками. Если тесты делят общее состояние (объект или мок) и его не сбрасывать, второй тест «наследует» след первого и падает. Лечится это хуком `beforeEach`, который Jest вызывает перед каждым тестом.

---

## Задание 1. `createCounter` — свежее состояние через `beforeEach`

Реализуйте фабрику счётчика `createCounter()` в `counter.js`:

**Спецификация.**

- возвращает объект-счётчик со своим внутренним значением (стартует с `0`);
- метод `increment()` увеличивает значение на 1 и возвращает новое значение;
- свойство `value` отдаёт текущее значение.

**Тесты.** Напишите **два** теста:

- [ ] один `increment()` → `value` равно `1`;
- [ ] два `increment()` → `value` равно `2`.

Ключевое: создавайте **свежий** счётчик перед каждым тестом в `beforeEach`, а не один на весь файл.

> Проверьте себя: временно вынесите `createCounter()` наверх файла (один на оба теста) и запустите — второй тест покажет `3` вместо `2`. Это и есть протекание состояния. Верните `beforeEach` — снова зелено.

---

## Задание 2. `saveAll` — сброс мока между тестами

Реализуйте `saveAll(storage, items)` в `saveAll.js`:

**Спецификация.**

- для каждого элемента массива `items` вызвать `storage.save(item)`;
- вернуть количество сохранённых элементов (`items.length`).

**Тесты.** Используйте общий мок `save = jest.fn()` на оба теста (как в реальных наборах) и напишите:

- [ ] один элемент → `save` вызван **1 раз** (`toHaveBeenCalledTimes(1)`);
- [ ] два элемента → `save` вызван **2 раза** (`toHaveBeenCalledTimes(2)`).

Общий мок **копит** вызовы между тестами — сбрасывайте его в `beforeEach`.

> Без `mockClear` второй тест увидит `3` вызова вместо `2` — мок помнит вызов из первого теста. Напоминание из лекции: `mockClear` стирает только историю вызовов; если бы вы задавали `mockReturnValue`, для его сброса понадобился бы `mockReset`.

## Критерии готовности

- [ ] `createCounter` и `saveAll` реализованы по спецификации.
- [ ] В каждом задании по два теста, и они **не зависят** от порядка запуска.
- [ ] Состояние готовится/сбрасывается в `beforeEach` (объект — пересоздаётся, мок — `mockClear`).
- [ ] `npm test` — все зелёные.
